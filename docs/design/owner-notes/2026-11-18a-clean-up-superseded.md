# Owner rule: clean up what is superseded

Said by the owner in chat on 18 November 2026, after the night run's orchestrator left two folders in place because it had only been told to clear the Codex worktrees.

> I don't want you to not delete things that are not needed anymore. If something already exists somewhere else, if something exists in its proper location and is backed up, or something has become superseded, it is code that is replaced or documentation that is stale, it should be deleted or cleaned up. If you don't want to think of it as deleting, think of it as cleaning it up. It needs to go because it's been replaced. It's not being deleted. It's being cleaned up because it's been replaced. It's superfluous. It's deprecated.

*[Editor note: this covers worktrees, branches, scratch folders and media as well as code and docs. Large files leave the machine only once they are in R2 (`tools/assets/`), and branches only once their work is merged or pushed. Git history keeps what is removed from the repo.]*
